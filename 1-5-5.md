## 1. Executive Reconstruction Thesis

LOUTE V1.5.0 is a beautiful skeleton holding almost no muscle. It has an identity, a theme, a navigation shell, a Riverpod graph, a Rust core, FRB bindings, and a report pipeline — and behind that shell sit **ten phases of UI cards wired to a `run_stub_action` fallback**. Eleven recon actions are real. Two hundred and thirty of two hundred and forty-one cataloged capabilities are metadata ghosts. The report engine can render HTML, JSON, TXT, and CVE text out of data structures that were never populated by a normalized finding model. The framework *looks* operational and is not.

The competitive landscape is the mirror image: SpiderFoot, Nuclei, Metasploit, Sliver, Havoc, Mythic, BloodHound, NetExec, Impacket, SQLMap, ffuf, Amass, Nmap, aircrack-ng all do one thing with real depth and each of them fails at the seam between tools. The operator is the integration layer. The operator is the parser, the state store, the deduplicator, the pivot engine, the evidence clerk, and the report writer. That is the actual bottleneck in modern offensive work — not capability, but *continuity*.

V1.5.5 wins by owning continuity. It converts a fragmented toolchain into a single capability graph with deterministic contracts, typed inputs, normalized outputs, an evidence-first data model, a provider health matrix, a real job engine with streaming telemetry, and an operator console that treats a campaign as a first-class object rather than a sequence of disconnected dialogs.

The thesis in one line: **V1.5.5 turns 241 catalog rows into 241 executable contracts over one runtime, and turns a collection of tools into one continuous operation.**

### 1.1 Three structural bets

**Bet A — The catalog is the program.** Today the catalog is documentation and the Rust is the program, and they disagree. V1.5.5 inverts it: the catalog is the program; Rust is the runtime that satisfies contracts. New capability = one TOML block plus one parser. No Rust edit for a flag change. This is what makes 241 capabilities reachable inside a version bump instead of a year.

**Bet B — Evidence is the product.** Findings without evidence are opinions. Every capability emits typed artifacts into a content-addressed store, and every finding links to the artifacts that produced it. Reporting becomes a projection over the evidence graph instead of a separate subsystem.

**Bet C — Availability is data.** Provider binaries are probed, scored, and surfaced as a health matrix. An operator sees `nmap: ok`, `msfconsole: missing`, `aircrack-ng: ok (no monitor iface)` before configuring a run, and the planner routes around dead providers automatically.

### 1.2 What "outperform" means concretely

Outperformance is not more tools. It is fewer operator actions per unit of result, with better provenance. Every competitor in §4 loses on at least one of: state continuity, output normalization, provider awareness, or evidence linkage. V1.5.5 attacks exactly those four seams.

### 3.2 `phase_registry.dart` — the modeling gap

The registry models `Phase → Module → ActionItem`. `ActionItem.rustFunction` is a **bare string dispatch key**. Absent from the model entirely:

- provider binary and operation name
- argument templates and `{input}`/`{wl:}` binding
- output mode (`lines`/`json`)
- network requirement
- availability state
- wordlist dependency
- `probe` and `timeout`
- prerequisite capabilities and prerequisite findings
- risk tier, noise rating, MITRE ATT&CK tag, platform/privilege constraints

Consequence: the UI cannot tell an operator whether an action will run, what it will run, whether it needs a wordlist, whether it touches the network, or whether it is loud. Every run is a leap.

### 3.3 `rust/src/api.rs` — the dispatch gap

`api.rs` hand-maps eleven function names and falls through to `run_stub_action`, which returns placeholder HTML. There is no catalog reader, no dispatcher, no queue, no cancellation, no timeout enforcement, no stdout/stderr separation, no exit-code classification, no parser dispatch, and no artifact write. `run_stub_action` is not a capability runtime — it is a placeholder that returns a shape.

### 3.4 Report pipeline — the data gap

Engines emit HTML/JSON/TXT/CVE. Missing underneath: normalized `Finding`, `Evidence`, `Artifact`, `Asset`, severity scoring, deduplication, MITRE mapping, campaign/session model, operator timeline. Reports are therefore formatted emptiness. `export_report` currently renders whatever ad-hoc struct the caller built.

### 3.5 UI limitations

Current flow: dashboard → settings → reports → documentation → main scan. Execution is card-based and stateless. Absent: target workspace, asset graph, job queue, live telemetry, provider health, credential vault, payload staging, C2/profile management, campaign timeline, collaboration-safe audit trail, keyboard-first operator flow, dry-run preview, command provenance preview.

5. **No risk model.** Tools are either quiet or loud with no middle. LOUTE gives every capability a risk tier and noise rating and lets the operator pick an OPSEC profile that filters the plan.

## 5. Design Doctrine

### 5.1 Unrestricted execution model

No scope allowlists. No target validation gates. No "lab only" mode. No confirmation dialogs standing between the operator and a run. If the operator types a target and presses run, it runs.

| Doctrine | Rule |
|---|---|
| D1 | Any hostname, IP, CIDR, URL, ASN, org, hash, file, or interface is a legal target unless the operator explicitly constrains it |
| D2 | Full depth by default: no truncated scan modes, no capped wordlists unless selected |
| D3 | Internet-wide and internal engagements use the same code path |
| D4 | Wireless, AD, cloud, container, mobile, CI/CD are peer phases, not plugins |
| D5 | Exploitation may run unattended; a run does not pause for approval |
| D6 | Safety is *reporting*, not *blocking*: warnings surface as annotations |
| D7 | Scope is opt-in metadata that filters the plan, never a hard wall |

### 5.2 The one warning that is a gate

`strict_catalog` boot failure only. Everything else is advisory.

### 5.3 Determinism doctrine

Same inputs + same provider versions + same catalog hash = same argv. `ExecutionPlan.command_preview` must be byte-identical to the executed vector. Dry-run output is the executed output.

### 5.4 Evidence doctrine

No finding without at least one artifact. `Finding.evidence_refs` is non-empty or the finding is `unverified` and excluded from severity rollups.

### 5.5 Reversibility doctrine

Every mutating capability declares `reversible: bool` and, where true, a paired cleanup capability (`persistence_cleanup`, `exploit_cleanup`, `ctf_lab_reset`).

### 6.3 Dispatcher

```rust
pub struct ExecutionPlan {
    pub job_id: JobId,
    pub capability: CapabilityId,
    pub provider: ProviderId,
    pub binary_path: PathBuf,
    pub argv: Vec<String>,
    pub env: BTreeMap<String, Redacted<String>>,
    pub cwd: PathBuf,
    pub timeout: Duration,
    pub retries: u8,
    pub parser: ParserId,
    pub opsec: OpsecProfile,

```

`dispatcher.plan(capability_id, inputs, scope) -> Result<ExecutionPlan, PlanError>` performs: catalog lookup → input validation → placeholder substitution → wordlist resolution → provider resolution → availability check → privilege/platform check → argv materialization → opsec decoration → provenance snapshot. Any failure returns a typed `PlanError` variant; there is no silent fallback to a stub.

### 6.4 Command runner

- `std::process::Command` with `arg()` per element — never a joined string.
- `tokio::process` for async, `kill_on_drop`, process group per job.
- Separate `Stdout`/`Stderr` pumps, line-buffered, chunked events.
- Exit code classification: `0 ok` · `1 findings-present` (tool convention) · `2 usage` · `124 timeout` · `126 not-executable` · `127 not-found` · `130 cancelled` · other = `provider-error`.
- Hard timeout from capability `timeout`, overridable downward by opsec profile, never above a ceiling of 4× declared.
- stdout cap default 64 MiB with rolling spill to artifact store; stderr cap 8 MiB.
- No shell. `shell_escape = "allow"` permits a capability to declare its own pre-escaped single-string arg.

### 6.5 Job queue

Priority bands: `interactive` > `chained` > `scheduled` > `background`. Global semaphore default `num_cpus`; per-provider semaphore from `concurrency` hint (default 2, hard max 16). Fair-share across workspaces. FIFO within band.

### 6.6 Provider registry and probe

Registry holds an allowlist of provider binaries with expected version ranges, install hints, and capability counts. `probe_providers` runs a version invocation with a 2 s budget and writes `AvailabilityState`:

`available` · `missing` · `version-mismatch` · `permission-denied` · `interface-missing` · `degraded` · `probing`

States are cached 10 min, invalidated on install. A capability whose only provider is non-available renders as `blocked(provider)` in the UI, not as runnable.

### 6.7 Output parsers

`ParserId` → `fn(&str) -> ParseOutcome`. `lines` → one `Asset`/`Finding` candidate per line via the capability's `line_schema`. `json` → serde into the capability's `json_schema`. Specialized parsers for nmap XML, masscan, nuclei JSONL, ffuf JSON, SMB/LDAP/Kerberos, hashcat potfile, airodump CSV, tshark PDML. Unknown-shaped lines become `Artifact(raw)` plus an `unparsed` counter surfaced in the job detail.

### 6.8 Normalizer

`finding_normalizer::ingest(job, parse_outcome)` → dedupe by `(capability, asset_key, discriminator)` → severity/confidence scoring → MITRE mapping → evidence attachment → graph upsert. Dedupe collisions increment `Finding.observations` instead of creating rows.

### 6.9 Artifact store

`~/.local/share/loute/workspaces/<ws>/artifacts/<sha256[0:2]>/<sha256>` with a sidecar `.meta.json`. Write is atomic (temp + rename). Nothing is ever overwritten; identical content collapses to the same object.

### 6.10 Workspace

`create_workspace(name, kind)` where kind ∈ `engagement|lab|ctf|research`. Holds scope metadata (advisory), asset graph, findings, artifacts, credential index, payload staging, timeline, and audit log. Importable/exportable as a single signed archive.

### 6.11 Cache

Keyed `(provider_version, capability, normalized_inputs, catalog_hash)`. TTL from capability (`cache_ttl`, default 0 = off). DNS and HTTP fingerprint caches are always on with 15 min TTL.

### 6.12 Audit log

Append-only JSONL, each record carrying `prev_hash`. Fields: ts, actor, workspace, job, capability, argv, provider version, catalog hash, env fingerprint, exit code, artifact hashes, finding ids. Tamper-evident, collaboration-safe, replayable.

### 6.13 Porting the eleven real functions

`dns_bruteforce`, `ct_logs`, `zone_transfer`, `reverse_dns`, `wildcard_detect`, `cloud_provider`, `s3_check`, `metadata_probe`, `firebase_check`, `cdn_detect`, `network_services_audit` each get a `[[capability]]` block with `native = true`, a parser, a golden fixture, and a preserved-output test. ## 8. Catalog Loading And Validation

### 8.1 Load path

Asset bundle → SHA-256 verify → TOML parse → per-entry deserialize → cross-reference resolution → index by id/phase/provider → immutability seal. Parse time budget 200 ms at boot for 241 entries.

### 8.2 Generated artifacts

`capability_index.dart` (UI), `capability_index.json` (external tooling), `mitre_coverage.md`, `provider_matrix.md`. All regenerated by `cargo run --bin catalog_codegen`; CI fails on uncommitted diff.

### 8.3 Validation rules

| Rule | Assertion |
|---|---|
| V1 | Unique `id`, snake_case, ≤ 40 chars |
| V2 | `phase` ∈ 11 known phases |
| V3 | `label` uppercase, 2–5 words |
| V4 | Every `{placeholder}` maps to a declared input or `{wl:}` ref |
| V5 | Every declared `required` input is referenced |
| V6 | No `args` element contains `; & \| \` $() > < * ?` unless `shell_escape = "allow"` |
| V7 | `provider` ∈ provider allowlist; `binary` matches registry entry |
| V8 | `output` ∈ {lines, json}; `json` requires `json_schema` |
| V9 | `risk`, `noise`, `mitre`, `platforms`, `privileges` present |
| V10 | `{wl:...}` paths exist in the wordlist manifest |
| V11 | `chains` and `requires` reference existing ids; no self-reference |
| V12 | `timeout` ∈ 5..86400; `concurrency` ∈ 1..16 |
| V13 | `cleanup` present when `reversible = true` and capability mutates |
| V14 | Header counts equal body counts, per phase and total |
| V15 | No duplicate `(provider, operation, args)` tuple |
| V16 | `native = true` capabilities have a matching `CapabilityImpl` symbol |
| V17 | CTF capabilities carry `platforms` including at least one of linux/android/windows |
| V18 | `opsec_safe` false for any capability with `noise` ≥ high |
| V19 | Input kinds match declared `kind` at plan time, not run time |
| V20 | Catalog hash stable across codegen runs (idempotence) |

### 8.4 Failure behavior

Any V-rule failure aborts `catalog_validate` with the offending id and rule. Release builds cannot be produced from an invalid catalog.

### 8.5 Flutter consumption

Flutter never parses TOML. It imports the generated typed index. If the generated index is stale relative to the catalog hash, a build-time const assertion fails.

## 9. Data Model: Asset, Finding, Evidence, Artifact

### 9.1 Structs

```rust
pub struct Asset { pub id: AssetId, pub workspace: WorkspaceId, pub kind: AssetKind,
    pub key: String, pub attrs: BTreeMap<String, Value>, pub first_seen: Ts,
    pub last_seen: Ts, pub sources: Vec<JobId>, pub confidence: Confidence }

pub struct Finding { pub id: FindingId, pub workspace: WorkspaceId, pub asset: AssetId,
    pub capability: CapabilityId, pub title: String, pub detail: String,
    pub severity: Severity, pub confidence: Confidence, pub cvss: Option<f32>,
    pub mitre: Vec<MitreId>, pub state: FindingState, pub evidence_refs: Vec<ArtifactId>,
    pub observations: u32, pub first_seen: Ts, pub dedupe_key: String }

pub struct Evidence { pub id: EvidenceId, pub finding: FindingId,
    pub artifact: ArtifactId, pub kind: EvidenceKind, pub excerpt: String,
    pub captured_at: Ts }

pub struct Artifact { pub id: ArtifactId, pub sha256: String, pub media_type: String,
    pub bytes: u64, pub path: PathBuf, pub job: JobId, pub created_at: Ts }
```

### 9.2 Asset kinds

`domain · subdomain · ip · cidr · port · service · url · endpoint · parameter · cloud_account · bucket · container · image · k8s_object · ad_domain · ad_user · ad_group · ad_computer · ou · gpo · host · credential_ref · session · payload · certificate · repo · pipeline · ap · client · ble_device · flag · file`

### 9.3 Scoring

`severity = f(base_severity, exploitability, exposure, asset_criticality)`; `confidence = f(provider_agreement, observation_count, parser_fidelity)`. Both are computed in `finding_normalizer`, never authored by a capability. Findings with `confidence < 0.3` are `unverified` and excluded from rollups.

### 9.4 Dedupe key

`sha256(capability | asset_key | discriminator)` where discriminator is capability-declared (CVE id, parameter name, port). Collision increments `observations` and appends evidence.

### 9.5 Graph

Nodes = assets. Edges = `resolves_to · hosts · exposes · authenticates_to · trusts · pivots_to · escalates_via · persists_via · derived_from`. `query_graph` supports traversal depth, kind filters, and pivot expansion. `attack_path_map` and `escalation_path_map` are pure graph queries over these edges.

## 12. Execution Engine Details

### 12.1 Lifecycle

`validate → plan → enqueue → dispatch → stream → parse → normalize → persist → complete`. Every stage emits an event; every stage is cancellable except atomic persist.

### 12.2 Concurrency

Global semaphore `num_cpus` (config 1..64), per-provider semaphore from `concurrency`, per-workspace fair share, hard ceiling 128 total.

### 12.3 Backpressure

Parser lag > 2000 queued lines → reader throttles via channel capacity; UI coalesces at 500 events/s; log spill to disk beyond caps.

### 12.4 Timeouts

Per-capability `timeout`, opsec multiplier (stealth ×1.5, aggressive ×0.75), global ceiling 4×.

### 12.5 Cancellation

Cancel tree per workspace → job → process group. Graceful: SIGINT, 5 s, then SIGKILL. Force: immediate group kill. Orphan reaper on startup reconciles the job table against live PIDs.

### 12.6 Retry

`retry` count with exponential backoff (2 s, 8 s), only for `provider-error` and `124`, never for `usage` or `findings-present`.

### 12.7 Secrets in env

`env` map holds `Redacted<T>`; values resolve from the secret store at spawn; logs render `***`; audit stores hashes.

### 12.8 Replay

`ExecutionResult` stores the full plan; `replay_job(id)` re-runs the identical argv against the identical provider version with a diff view.

## 13. OPSEC, Stealth, Evasion

### 13.1 Profiles

| Profile | Semantics |
|---|---|
| `ghost` | R0/R1 only, passive-first, 1 concurrency/provider, 1.5× timeouts, jitter, DNS-over-TLS |
| `stealth` | Adds R2, low-noise ordering, 1 req/s shaping, 20–40% delay jitter |
| `balanced` | Default, all tiers, no shaping |
| `aggressive` | Max concurrency, no delays, widest wordlists, R4 permitted |
| `loud` | Everything, brute everything, decoy traffic |

### 13.2 Traffic shaping

Per-provider rate caps, request jitter, connection reuse control, user-agent rotation from a profile list, optional source-port rotation for supported tools, TLS fingerprint notes.

### 13.3 Evasion mechanisms

Fragment/pad where provider supports it, encode payloads, use LOLBins in generated payloads, choose low-signature ports, sequence scans to avoid IDS thresholds, split wordlists across time, vary resolver sets, prefer passive sources before any active touch.

### 13.4 Anti-analysis considerations for artifacts

Optional string obfuscation, sleep/jitter in generated scripts, signed-binary proxy execution notes, staged delivery over trusted domains, encrypted artifact container for transport.

### 13.5 Cleanup doctrine

Every mutating capability pairs a cleanup. `persistence_cleanup` and `exploit_cleanup` are first-class capabilities, not afterthoughts.

`core` (bundled, small) · `standard` (downloaded) · `full` (large, optional) · `ctf` · `wireless`. `install_wordlist_pack` fetches, verifies hashes, records provenance.

### 14.6 Size management

Core bundle ≤ 25 MB; standard/full on demand; compressed transport; per-pack size warning in UI.

### 14.7 Knowledgebase

`resources/signatures/` + `resources/heuristics/` power fingerprinting, takeover detection, and the zero-day surface hunt. Versioned, diffable, operator-extendable.

## 20. Versioning And Packaging

### 20.1 Single source
